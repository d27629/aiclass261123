# 定價心法

> 這是**挖空模板**。標 ★ 的地方要你自己填，每一條都要寫「理由」。
> 填的內容來自你自己玩遊戲的經驗：哪些價格客人會買、哪些會嫌貴、星等怎麼變。

## 什麼時候用

AI 店長要決定某一天每樣菜的定價時。

## 一定要遵守的規則（來自規則書，不可以改）

- 定價只能在菜單的可定價範圍內（見 `web-lab/src/game/menu.js` 的 minPrice～maxPrice）
- 客人只有在「價格 ≤ 剩下的預算」時才會買
- 價格 ≤ 建議售價，客人買到第一順位才會「滿意」；滿意的人多，星等才會升

## 我的定價心法

心法 1（什麼時候該定在建議售價以下？）：降價需要有實際結果支持，例如試算或盤點顯示「嫌太貴」造成買不到，或想實驗價格對滿意度的影響。一次只降一樣菜，並在回報中說明降了多少。
理由：降價會犧牲單份收益（每份少賺的錢），沒有實際結果就降價，等於白白少賺。規則書規定客人只有「價格 ≤ 剩下的預算」才會買、價格 ≤ 建議售價才會「滿意」，所以降價有機會讓更多人買到、滿意的人變多。但這是要靠下一版試算驗證的假設，不是已證明的規律。

心法 2（什麼時候可以漲價？漲到多少？）：漲價必須在該菜的可定價範圍內（見規則書菜單），並說明可能影響購買、滿意度與後續來客數。不把「缺貨」直接當成「漲價一定有效」的證據。
理由：價格一旦超過建議售價，客人即使買到也不算「滿意」，滿意比例下降會讓星等往下掉，隔天來客數（星等 ×0.6～×1.4）也跟著變少。缺貨只代表貨不夠，不代表客人願意付更高的價錢，所以漲價前要先確認客人預算是否還買得起。

心法 3（第一版基準：飲料和鍋貼是否用不同策略）：第一版先全部使用建議售價，建立比較基準。之後每一版最多改 3 個地方，才看得出是哪個修改造成差異。
理由：沒有基準就沒有比較。固定建議售價當作第一版，之後降價、漲價、改備貨量的效果，才能和同一個基準對照，而不是和感覺比。

## 回報格式

```text
第 N 天定價：
| 菜 | 定價 | 用了哪一條心法 |
```

## 不准做的事

- 不准定在可定價範圍以外
- 不准修改任何遊戲檔案
