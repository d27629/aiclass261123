# 客人資料製作

> 這是已完成自訂的 Skill 模板。標 ★ 的地方已填入主題、預算及自訂規則，每一項均附理由。
> AI 每次幫忙產生客人時，都必須遵守以下規則。

## 什麼時候用

使用者說「幫我做一批新客人」「我要出題考同學」時。

## 每位客人必須有這些欄位

| 欄位 | 意思 | 限制 |
|---|---|---|
| name | 名字 | 不可用真實名人、不可重複 |
| intro | 一句話介紹 | 20 字以內 |
| budget | 一餐的總預算 | 30～150 的整數 |
| wants | 想吃的東西，有先後順序 | 1～2 樣，只能從菜單選 |
| hates | 討厭的東西 | 最多 1 樣，沒有就寫 null |
| days | 出現在第幾天 | 1～5 的整數陣列，例如 [1, 3] |
| count | 當天的基本人數 | 1～12 的整數 |
| lines | 五種情況的台詞 | 每句 20 字以內，五句都要有 |

`lines` 的五種情況：

- `bought`：買到了
- `hated_on_menu`：討厭的東西有上架，不進門
- `not_on_menu`：想吃的沒上架
- `sold_out`：想吃的賣完了
- `too_expensive`：太貴不買

## 菜單（只能從這六樣選）

招牌鍋貼、韭菜鍋貼、玉米鍋貼、酸辣湯、豆漿、紅茶

## 這批客人的主題

★ 主題：
辦公室午休生存戰。

請設計三位不同職業與消費習慣的上班族客人：

1. 小急業務阿哲：午休時間有限，偏好招牌鍋貼與紅茶。
2. 精算行政小米：注重午餐預算，偏好玉米鍋貼與豆漿。
3. 加班工程師阿凱：工作忙碌，偏好韭菜鍋貼與酸辣湯。

三位客人都必須有不同的消費預算、飲食偏好及個性台詞。

★ 理由（為什麼選這個主題？）：
以辦公室上班族的午休情境為主題，貼近實際生活。
透過業務、行政人員與工程師不同的消費習慣，
增加經營遊戲的變化與趣味性，
讓玩家需要考量餐點上架、備貨量與價格設定。

## 預算範圍

★ 這批客人的預算要落在幾元到幾元之間（必須在 30～150 之內）：
60～150 元。

三位客人的預算分別設定為：
- 小急業務阿哲：65 元
- 精算行政小米：90 元
- 加班工程師阿凱：85 元

★ 理由：
模擬不同上班族的午餐消費能力。
行政人員重視節省開支，
業務人員追求方便與效率，
工程師預算有限，常常只買得起一樣主餐。
藉由不同預算，讓遊戲出現因價格而放棄購買的情境。

## 工作步驟

1. 先讀 `web-lab/src/game/menu.js`，確認菜單與建議售價
2. 先產生 3 位客人，用表格給使用者看，**不要直接寫檔**
3. 使用者說 OK，才寫入 `web-lab/src/game/customers/my-customers.json`（整個檔案是一個陣列）
4. 寫完執行下面的檢查，逐條回報結果

## 寫完必須檢查

- 必填欄位都有，五句台詞都有
- budget 在 30～150 之間，也在上面填的預算範圍內
- wants、hates 只用菜單上的品項
- 沒有重複的名字
- 每一天的 count 加總不超過 50
- 在 `web-lab` 資料夾執行 `npm run check`，確認「客人包檢查」仍然全部 PASS
- 打開遊戲，在「客人包」選「我的客人包」，確認沒有出現紅色錯誤

- ★ 我自己加的檢查規則：
  1. 三位客人的預算必須不同。
  2. 三位客人的第一優先餐點不可相同。
  3. 三位客人都必須具備不同的個性台詞。
  4. 五種情境的台詞必須符合實際購買結果。
  5. 每位客人至少出現在遊戲五天中的其中一天。

- ★ 這條規則要擋掉什麼樣的客人：
  避免產生預算、喜好與台詞都相同的客人。
  避免客人在商品售完時說成太貴，
  或在商品未上架時說成已經售完。
  同時避免客人沒有安排出現日期，
  導致玩家無法在遊戲中體驗自訂客人。

## 不准做的事

- 不准新增菜單沒有的品項
- 不准新增欄位或修改遊戲規則
- 不准改 `my-customers.json` 以外的檔案

- ★ 我自己加的禁止事項：
  1. 不可以讓三位客人的預算完全相同。
  2. 不可以讓三位客人都喜歡同一項主要餐點。
  3. 不可以新增遊戲不存在的食物。
  4. 不可以讓台詞與購買失敗的原因矛盾。
  5. 不可以使用真實名人的名字。

- ★ 理由：
  確保三位客人都有鮮明特色，
  並且符合遊戲既有的格式與規則。
  避免錯誤資料影響遊戲運作及自動驗收。
  也讓玩家能透過不同客人的需求，
  練習備貨、定價及菜單組合的經營決策。
